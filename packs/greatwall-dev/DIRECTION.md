## 一、耗时限制（未做）

### 现状：内核已经有旋钮，但只能在设置面板里调，而且粒度太粗

| 设置项 | 默认值 | 管什么 |
|---|---|---|
| `tool_timeout_secs` | 120 | 单次工具调用最长多久 |
| `mcp_timeout_secs` | 60 | 单次 MCP 调用最长多久 |
| `subagent_max_steps` | 12 | 子代理最多几步 |
| `subagent_wall_secs` | 900 | 子代理最多跑多久 |
| `subagent_max_depth` | 2 | 子代理最多嵌套几层 |
| `job_wait_secs` | 30 | 等待后台任务的单次上限 |
| `max_steps` | 50 | 主代理最多几步 |

**问题**：这些是**全局设置**，改了影响所有对话、所有任务。而实际需要的是**按任务给预算**——
一个查天气的任务不该和一次重构共享 900 秒。

### 目标

**1. 主代理能给子代理指定预算**

```
delegate(task, budget={steps: 20, wall_secs: 300, tool_timeout: 60})
```

现在的 `delegate` 只能传任务文本，预算靠全局设置。工具描述里承诺的“十二步”是写死的。

**2. 主代理能给单个工具调用指定超时**

```
bash(command, timeout_secs=600)     # 这一次允许跑十分钟
```

现在的 120 秒是全局的，一个 `cargo build` 撞上了就失败，而别的工具又被允许得太长。

**3. 题板上的票自带预算**

开票时写清这张票允许花多少：步数、墙钟、工具超时。worker 按票的预算跑，
而不是按全局设置。票超预算就停下来报告，不是继续烧。

**4. MCP 调用单独计时**

MCP 的慢和本地工具的慢不是一回事：MCP 卡住通常是子进程死了或网络断了。
现在 `mcp_timeout_secs=60` 到点失败，但**没有区分“慢”和“死”**——
一个还在正常工作的慢 MCP 会被杀掉，而一个已经死掉的需要等满 60 秒。

### 实现路径（建议）

- 内核：`ToolDef` 加可选 `timeout_hint`，`ToolRegistry::execute` 尊重调用方传入的超时
- 内核：`delegate` 工具加 `budget` 参数，透传到子 agent 的 `Agent::max_steps` 等字段
- 包：票的 JSON 里加 `budget` 字段，worker 启动时读它
- 包：`ticket-mcp.mjs` 提供 `ticket_budget` 查询

**优先级**：第 1 项（delegate 带预算）最有用，因为它是现在最缺的。

## 二、让 AI 多用后台和子代理（未做）

### 现状：内核支持，但没有任何东西推着 AI 去用

- `bash(background: true)` 能起后台任务
- `job_output` / `job_list` / `job_kill` 能管它们
- `delegate` 能派子代理

**但这些能力全靠 AI 自己想起来。** 实测的问题：AI 会串行等一个 3 分钟的上传，
而不是派给后台然后干别的。这不是能力缺失，是**提示词里没有这条规矩**。

### 目标

**1. 把“能后台就后台”写进 soul，并且给出判断标准**

不是笼统地说“多用后台”，而是：

- 超过 30 秒的操作 → 后台
- 不依赖结果的独立工作 → 子代理
- 等待期间必须有别的事在做

**2. 后台任务也要有预算**

```
bash(background: true, timeout_secs=3600)    # 后台跑一小时，超时就杀
```

现在的后台任务没有超时概念，起了一个跑飞了要人手动 `job_kill`。

**3. 子代理的产出要能持久化并查看**

现在的子代理跑完就没了。主人要求过：
- 能看到子代理输出什么
- 把子代理的输出持久化

子代理的转录在 `.ngu-subtasks/*.jsonl`，但没有界面能看，也没有工具能读。

**4. 票板要能显示“谁在后台干什么”**

一张票派出去之后，主代理应该能一眼看到：
- 几个 worker 在跑
- 各自跑了多久
- 谁的预算快用完

现在是盲的。

### 实现路径（建议）

- 包：soul.md 里写清判断标准（**这一条零成本，先做**）
- 内核：`bash` 工具认 `timeout_secs` 参数
- 包：`ticket-mcp.mjs` 加 `ticket_workers` 列出在跑的 worker
- 包：look.json 面板显示 worker 状态

## 四、设计原则

1. **预算跟着任务走，不跟着进程走。** 全局设置是默认值，不是上限。
2. **超时要能解释。** 失败了要说清是“超时了”还是“工具报错了”，两者处理方式完全不同。
3. **后台不是逃避。** 起了后台任务就要有人去看结果，起完不管比不启更糟。
4. **不静默。** worker 被预算掐停要报告，不能悄悄消失。
