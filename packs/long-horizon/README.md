# long-horizon —— 长程任务包

给**超过上下文窗口几十上百倍、跨天跨周**的任务用。它不是"更长的对话",而是
把任务本身搬到磁盘上:对话只是执行它的**一次载体**。

装上这个包,你得到八个工具和一个界面上的任务条。

## 机制一览

| 工具 | 干什么 |
|---|---|
| `mission_start` | 开任务:目标 + 完成判据 + 第一步,落在 `<workspace>/missions/<id>/` |
| `mission_status` | 读当前状态(几十行,不读历史)——开工第一件事 |
| `mission_advance` | 记账:这一步做了什么、下一步是什么、状态改没改 |
| `mission_checkpoint` | 里程碑快照(当时的 STATE.md + 任务记录),回滚与交接点 |
| `recall` | 按行检索任务记忆(日志/STATE/检查点/信箱),返回文件+行号 |
| `mission_tick` | **在全新 worker 里跑一步**:worker 拿到 objective + done_when + STATE.md + 这一步,干完把报告和"下一步"写回来 |
| `agent_post` | 给另一个代理投信(信箱落盘,收件人不在跑也收得到) |
| `agent_inbox` | 读自己的信,读过的不会重复投递 |

界面上多一条**任务条**(在输入框上方):显示任务号/状态/下一步/检查点数/未读信件,
带「刷新」和「推进一步」两个按钮。

## 三个设计决定(为什么这样做)

1. **状态在会话工作区里,不在内核里**。
   放在 `<workspace>/missions/` 意味着:模型自己的 `read`/`write`/`edit` 能直接
   读写它,网页界面能把它当文件下载,工作区快照覆盖它。**没有新的存储层**。

2. **日志只追加,记忆靠检索**。
   `log.jsonl` 是一行一条 JSON 的事实记录。长任务的成本大头是"回忆自己干了什么",
   所以这里的规矩是:**永远不要重读历史,`recall` 搜出那几行**。上下文只装当前
   这一步需要的东西。

3. **一步 = 一个短命的 worker**。
   `mission_tick` 起的是**空历史**的子代理:它只拿到任务的目标、完成判据、当前
   STATE 和这一步的描述。这是长任务的唯一可持续形态——许多个短命载体,而不是
   一个被压缩到失真的长会话。

## STATE.md 的约定

```markdown
# 任务 m-…

<!-- mission:generated -->      ← 自动维护,别手改
## 当前（自动维护，别手改这一段）
- 状态：running
- 下一步：…
- 推进 3 次 · 检查点 1 个 · 更新于 …
<!-- /mission:generated -->

## 目标         ← 以下都是你的地盘
## 完成判据
## 决策记录      ← 为什么这样、放弃了什么
## 阻塞与风险
## 备注          ← 给下一个接管者的话
```

围栏之外的内容**永远不会被工具覆盖**——工具只重写围栏之间那一段。

## 稳健性

- 每次写盘都是「临时文件 + rename」,崩在写一半不会留下半个 `mission.json`;
- 日志与信箱是**追加写**,一条一次 `write_all`;
- 读盘一律解析成 JSON 后显式取值:缺字段走默认,**坏了报文件名**(不是 panic);
- 没有任务时的报错是**指路**(告诉你怎么开一个),不是干巴巴的失败;
- 信箱地址经过净化,`../` 之类不可能变成任务目录之外的路径。

## 装上它

```bash
ngu pack packs/long-horizon            # 打成 .dshpack
ngu install packs/long-horizon/long-horizon-1.0.0.dshpack
```

或者网页界面里 **Install…** 选这个 `.dshpack`。装好后**启用**(Load)一次,
任务条和八个工具就出现了;卸载后一切消失,任务目录留在工作区里不动。

## 配套技能

`skills/mission-protocol` —— 协议本身(什么时候开任务、STATE 怎么维护、一步的
粒度、记忆怎么用、代理怎么通信、怎么交接)。包启用后按需加载。
