# 设计：会话用量统计落盘（usage stats persistence）

状态：已实现。立项依据：10-22 `api-debug.txt` 自查结论"缓存字段的解析和统计管道已经存在，但没落盘"；
当时 `src/session.rs` 的 `JsonlLine` 无用量行型，`main.rs`/`desktop/state.rs` 只即时打印或推送 usage。

落地形态与本文一致：`JsonlLine::Stats` 行型、`totals_of` 聚合、`ngu stats`（单会话 / `--all` / `--json`）、
桌面 `stats` 命令走并发车道。相比立项时多了一个字段 `cache_created`——provider **写进**缓存的
prompt token 数，与 `cached`（从缓存读出来的）分开记账：两者计费方式相反（写通常加价、读打折），
合在一起的账没法换算成钱。JSON 与命令行人读输出都带它。

## 目标

每个回合（turn）结束时，把该回合的 token 与耗时统计作为一行 JSONL 追加进会话文件；
提供 CLI 子命令、serve 命令与桌面/网页端聚合展示。原则对齐 DeepInfer 启发笔记："可观测"。

## 数据模型（src/session.rs）

```rust
#[derive(Debug, Clone, Default, Serialize, Deserialize, PartialEq, Eq)]
#[serde(default)]
pub struct TurnStats {
    pub ts: String,            // RFC3339，回合结束时刻
    pub steps: u32,
    pub tool_calls: u32,
    pub retries: u32,          // 无则为 0
    pub input: u64,            // prompt tokens（含 cached，provider 语义）
    pub output: u64,
    pub cached: u64,           // provider 从缓存**读出**的 prompt tokens
    pub cache_created: u64,    // provider 本轮**写进**缓存的 prompt tokens
    pub reasoning: u64,        // TokenUsage.reasoning，缺 0
    pub model_ms: u64,
    pub tools_ms: u64,
}
```

- `#[serde(default)]` 在结构体上：被截断或手改过的行缺字段也能读回，不会因为一行失败整份加载。
- `TurnStats::from_outcome(&AgentOutcome)` 从循环的汇报里取全字段；`TurnStats::unreported()`
  给"回合没来得及汇报就死了"写一行全 0（`ts` 照写）——写而不是跳，回合数才诚实。
- `JsonlLine` 新增 `Stats(TurnStats)`，serde tag `"type": "stats"`。必须是**结构体**变体：
  内部标签的枚举只能把结构体缓冲成 map，`Packs` 那种包 `Vec` 的 newtype 根本序列化不出来（笔记 10-12）。
- `load()`：`Stats` 行收集进 `StoredLines.stats`，再落到 `Session.stats: Vec<TurnStats>`（默认空）。
- `list()` 摘要路径经 `read_header` 把 `Stats` 归入"不携带消息"的分支——列表不携带统计正文；
  `touch()` 读同一个函数，所以重写表头也不会把用量行当成消息计数。
- **表头重写路径**（`touch`，被 `append`/`append_compaction`/`append_packs`/`append_stats` 共用）只重写第一行：
  其余行原样逐字复制进同目录临时文件，sync 后 rename 覆盖——要么旧文件、要么完整的新文件。
  消息可以被 compaction 折叠，统计是会话级账本，一行都不能丢。
- 旧文件兼容：未知行跳过逻辑已存在，新增行型自然向后兼容；`SessionTotals` 上的 `#[serde(default)]`
  让老构建写下的、没有 `cache_created` 的总计对象照样能读回。

## 记录点（三处，共用一个 helper）

`TurnStats::from_outcome(...)` ＋ `JsonlStore::append_stats(&self, id, &TurnStats)`
（与 `append_packs` 同构：append-only，`writeln!` 后 `flush` 再 `sync_data`——只 flush 停在内核缓冲，
那就等于没为"断电后还看得见"这件事做任何事）。CLI 的两处经 `main.rs` 的 `record_turn_stats` 收口，
失败只打 `[stats] ...`；桌面自己调用 `append_stats`（`[store] stats append failed: ...`），
同样不把已完成的回合变成失败回合。

1. `src/main.rs` 一次性 CLI 路径（`record_turn_stats`：成功收 `from_outcome`，硬失败写 `unreported`；
   打印模式与 `--json` 共用同一个 outcome）。
2. `src/main.rs` `interactive()` 每回合收尾处（成功收 `from_outcome`；回合出错时写 `unreported`）。
3. `desktop/src/state.rs` `run_turn` 收尾处：行写成功才 push 进内存会话，
   所以面板上的总计只可能落后于文件一行，不会多算一行。

注意：三处都不在锁内做 IO 跨 await；沿用短锁纪律。

## 聚合（src/session.rs）

```rust
pub struct SessionTotals { turns, steps, tool_calls, input, output, cached, cache_created, reasoning, model_ms, tools_ms }
impl SessionTotals { pub fn cache_hit_ratio(&self) -> f64 /* cached / input, input==0 → 0.0 */ }
impl std::iter::Sum for SessionTotals;   // 跨会话合计就靠它
pub fn totals_of(session: &Session) -> SessionTotals;
```

- `cache_hit_ratio` 是 0..=1 的比例，不是百分数：两个前端都直接拿去乘 100，谁也不用重做一次除法。
  零 prompt token 时返回 0.0 —— "没输入"不是一个完美的命中。
- `totals_of` 对没有用量行的会话（这份账存在之前写的所有会话）返回全 0，不报错：
  没有账本不等于读失败。`retries` 不进合计（它是回合内重试次数，跨回合相加没有含义）。

## 接口面

### CLI：`ngu stats`（单会话）与 `ngu stats --all`（跨会话）

```
ngu stats                     # 最近更新的那个会话
ngu stats <session_id>        # 指定会话；文件不在就报 (not found)
ngu stats --all               # 每个已存会话一段，末尾一段 grand total
ngu stats --json [<id>]       # 机器可读；--json 是全局选项，位置随意
ngu --home <dir> stats        # --home 就是会话存储根本身（<id>.jsonl 在其下）
```

人读输出，每个会话一段（`stats_command` → `print_stats_block`）：

```
session <id>
  turns 2  steps 5  tool calls 4
  tokens  in 300  out 14  cached 125  written 22  hit 41.7%  reasoning 6
  time    model 800 ms  tools 50 ms
```

- `written` 就是 `cache_created`：本轮写进缓存的 token 数，和 `cached`（读出来的）并列显示。
- `hit` 是 `cache_hit_ratio * 100`，一位小数。
- 该会话没有用量行时只打印 `no turns recorded`；id 的文件不存在时首行带 `(not found)`，数字按 0 出。
- 总计段的标题就是 `total`，当 `--all` 或"载入了不止一个会话"时打印 —— 一行有时出现有时不出现的报告，
  脚本没法读，所以宁可单会话 `--all` 也照打。
- 人读输出**不**逐回合列行：尾 20 条只出现在 `--json` 里，汇总才覆盖整个会话。

`--json` 的形状（`stats_totals_json` / `stats_turn_json`）：

```json
{
  "sessions": [
    { "session": "<id>", "found": true,
      "totals": { "turns": 2, "steps": 5, "tool_calls": 4, "input": 300, "output": 14,
                  "cached": 125, "cache_created": 22, "reasoning": 6,
                  "model_ms": 800, "tools_ms": 50, "cache_hit_ratio": 0.4167 },
      "turns": [ { "ts": "2026-10-22T09:00:00+08:00", "steps": 1, "tool_calls": 2,
                   "retries": 0, "input": 100, "output": 7, "cached": 25,
                   "cache_created": 11, "reasoning": 3, "model_ms": 400, "tools_ms": 50 } ] }
  ],
  "total": { "turns": 2, "steps": 5, "tool_calls": 4, "input": 300, "output": 14,
             "cached": 125, "cache_created": 22, "reasoning": 6,
             "model_ms": 800, "tools_ms": 50, "cache_hit_ratio": 0.4167 }
}
```

- `turns` 是**尾 20 条**（`STATS_TAIL`），只有非 `--all` 时才给：`--all` 的逐会话明细会把总计埋掉。
- `found: false` 用于"这个 id 没有文件"，两者都按 0 出 —— 打错 id 和删掉的会话，答案都是"没记过账"。
- 一个会话都没有时输出 `{"sessions": [], "total": {...全 0}}`；人读路径改打 `no sessions in <root>`。
- 字段名是契约：桌面 `totals_json` / `turn_stats_json` 从同一个结构体拼同一套名字，脚本读哪一端都一样。

### serve / desktop dispatch

- 命令 `"stats"`：入参可选 `session`，返回 `{ "session", "totals", "turns" }`，`turns` 是尾 20 条
  （`desktop/src/state.rs` 的 `stats`，全程从已载入的行里读，不碰 IO、不写）。
  请求别的会话时才去 store 再读一遍，所以两个会话的数字不会串。
- `desktop/src/serve.rs` 的 `is_concurrent()` 白名单含 `stats`（只读命令，直接 spawn 车道），
  回合运行中也能即时返回。
- 窗口模式把 `totals` 直接挂进 `status` 推送（`ready` 与每次状态变更都带），页面无需第二次往返。

### UI（`desktop/ui/index.html`）

面板上那行文本由 `renderUsageTotals` 画，`status.totals` 或 `stats` 命令的 `totals` 都可能喂它：

```
Tokens: 12.3k in / 456 out / 7.8k cached · 命中率 63.4% · turns 12 · tools 40
```

- `cache_created` 在 `totals` 载荷里（`written` 不在这一行文本上）—— 面板只画读命中；要换算成钱看
  `ngu stats` 或 `--json`。
- **同步约束**（`tests/ui_sync.rs`）：`desktop/ui/index.html` 与 `packs/starter/index.html` 必须逐字节一致，
  改 UI 后按该测试注释执行 `cp desktop/ui/index.html packs/starter/index.html` 并重打包
  `ngu pack packs/starter --out packs/starter/starter-1.0.0.dshpack`。另注意该测试第二条：新增 `set-*` 元素 id
  若被脚本使用必须有 `const/let` 声明。

## 验收

实现后按下列各条核对（单测在 `src/session.rs` 的 stats 测试组，桌面在 `desktop/src/state.rs` 的 `stats_tests`）：

1. 新单测（session.rs）：`append_stats` → `load` 回放得 Vec；`touch`（表头重写）/compaction 后 Stats 行不丢。
2. 集成测试（tests/kernel.rs 风格）：跑一个 mock 回合后 stats 落盘且 `ngu stats --json` 可读（或 lib 级 totals_of）。
3. serve 实测：回合运行中 `stats` 命令即时返回（并发车道）；两会话统计互不串。
4. 旧会话文件（无 stats 行）加载不报错、totals 全 0。
5. `cargo test --lib`、`cargo test --tests`、desktop check 全绿。
